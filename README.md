# MQTT Kafka connector

## Обзор проекта

Данный проект представляет собой коннектор на основе Python, соединяющий брокера MQTT и кластер Kafka. Основная задача приложения заключается в подписке на заданные темы MQTT, обработке входящих сообщений и публикации их в соответствующие темы Kafka.

Коннектор построен с использованием современных асинхронных библиотек Python:

-   `aiomqtt` для обработки коммуникаций MQTT.
-   `aiokafka` для взаимодействия с кластером Kafka.
-   `fastavro` и реестр схем для десериализации сообщений, закодированных в формате Avro.
-   `aioprometheus` для экспонирования метрик.

Настройка осуществляется посредством переменных окружения, которые могут загружаться из файла `.env`. Точка входа основного приложения находится в файле `src/mqtt_kafka_connector/connector/main.py`.

Приложение предназначено для запуска в контейнеризированной среде обслуживания, при этом предоставляются файлы `Dockerfile` и `docker-compose.yml` для сборки и запуска коннектора.

## Сборка и запуск

### Зависимости

Зависимости проекта управляются с помощью инструмента `uv` и определены в файле `pyproject.toml`.

### Локальная разработка

**1. Настройка переменных окружения:**

```shell
cp .env.example .env
```

После чего внесите изменения в файл `.env`.

**2. Запуск приложения:**

```shell
make run
```

Альтернативно, после установки зависимостей, можно воспользоваться скриптом, определенным в файле `pyproject.toml`:

```shell
mkc
```

### Docker

-   **Сборка образа Docker:**

    ```shell
    docker build --no-cache -t piklema/mkc:latest .
    ```

-   **Запуск с Docker Compose:**
    Файл `docker-compose.yml` настроен для запуска сервиса коннектора.

## Тестирование

### Unit-тесты

Для запуска юнит-тестов выполните команду:

```shell
make test
```

### E2E-тесты

Для запуска end-to-end тестов, которые проверяют взаимодействие с реальными сервисами (Kafka, MQTT), выполните следующие шаги:

**1. Запустите сервисы:**

В одном терминале запустите Docker-контейнеры с необходимыми сервисами:

```shell
docker-compose -f docker-compose.e2e.yml up -d
```

**2. Запустите коннектор в режиме тестирования:**

В другом терминале запустите приложение-коннектор со специальным флагом `E2E_TESTING`, который включает мокирование Schema Registry:

```shell
E2E_TESTING=true uv run mkc
```

**3. Запустите тесты:**

В третьем терминале запустите сам e2e-тест:

### 3. Запустите тесты:

В третьем терминале запустите сам e2e-тест:

```shell
uv run pytest tests/test_e2e.py
```

### Запуск с мониторингом

Для запуска E2E-тестов вместе с сервисами мониторинга (Prometheus и Grafana) используйте профиль `monitoring`:

```bash
docker-compose -f docker-compose.e2e.yml --profile monitoring up -d
```

После запуска вы сможете получить доступ к:

-   Prometheus: `http://localhost:9090`
-   Grafana: `http://localhost:3000` (логин/пароль по умолчанию: `admin`/`admin`)

## Нагрузочное тестирование

Для проведения нагрузочного тестирования используйте Locust и эмулятор грузовиков.

### 1. Запуск инфраструктуры (MQTT брокер, Kafka, Prometheus)

Убедитесь, что у вас запущены MQTT брокер (например, Mosquitto), Kafka и Prometheus. Если вы используете `docker-compose`, вы можете запустить их командой:

```bash
docker-compose up -d
```

Убедитесь, что `mqtt-kafka-connector` также запущен. Если вы используете `uv`, то:

```shell
uv run mkc
```

(или соответствующая команда для запуска вашего приложения)

### 2. Запуск нагрузочного теста Locust

Запустите Locust:

```bash
uv run locust -f tests/load_test/locustfile.py
```

Откройте веб-интерфейс Locust в браузере (обычно по адресу `http://localhost:8089`). В интерфейсе Locust вы сможете настроить количество пользователей (N) и скорость их появления. Постепенно увеличивайте N, чтобы наблюдать за поведением системы.

### 3. Мониторинг задержки через Prometheus

Prometheus будет собирать метрики задержки, которые `mqtt-kafka-connector` отправляет. Вы можете получить доступ к веб-интерфейсу Prometheus (обычно `http://localhost:9090`) и запросить метрику `telemetry_message_lag_seconds`. Для более удобной визуализации и анализа рекомендуется использовать Grafana. Вы можете настроить Grafana для подключения к Prometheus и создания дашбордов, отображающих задержку в реальном времени.

### 4. Анализ результатов и отчет

Наблюдайте за метрикой `telemetry_message_lag_seconds` в Prometheus или Grafana. Зафиксируйте значение N, при котором средняя задержка начинает превышать 1 минуту (60 секунд). Проанализируйте другие метрики системы (CPU, память, I/O Kafka, MQTT) для выявления узких мест. Оформите отчет, включив графики зависимости задержки от N, выводы и рекомендации по оптимизации.

## Схема обработки сообщений

## Схема обработки сообщений

Приложение обрабатывает сообщения, поступающие из MQTT, и маршрутизирует их в соответствующие топики Kafka. Ниже представлена схема прохождения и обработки сообщения:

1.  **Поступление сообщения MQTT**: Сообщение поступает от брокера MQTT в коннектор.
2.  **Маршрутизация сообщения (`TopicRouter`)**:
    -   `TopicRouter` анализирует топик MQTT-сообщения.
    -   В зависимости от структуры топика, сообщение направляется либо в `TelemetryHandler`, либо в `FStateHandler`.
3.  **Обработка телеметрических сообщений (`TelemetryHandler`)**:
    -   Извлекает параметры из топика MQTT (например, `customer_id`, `device_id`, `schema_id`).
    -   **Обработка с помощью Middleware (`Pipeline`)**: Полезная нагрузка сообщения проходит через цепочку `middleware` (реализованных в `Pipeline`), которые выполняют такие операции, как декомпрессия, десериализация (например, Avro) и валидация схемы.
    -   Отправляет обработанные данные в Kafka, используя `kafka_producer.producer.send_batch` в соответствующий топик телеметрии.
4.  **Обработка сообщений о состоянии (`FStateHandler`)**:
    -   Извлекает параметры из топика MQTT (например, `customer_id`, `device_id`).
    -   Десериализует полезную нагрузку сообщения из JSON.
    -   Отправляет обработанные данные в Kafka, используя `kafka_producer.send` в соответствующий топик состояния.
5.  **Отправка в Kafka**: После обработки сообщение публикуется в кластер Kafka.

## Конвенции разработки

-   **Проверка стиля и форматирование:** Проект использует инструмент `ruff` для проверки стиля и форматирования кода.

    -   `make lint`: Проверка наличия проблем со стилем.
    -   `make format`: Автоматическое форматирование кода.

-   **Тестирование:** Тесты расположены в директории `tests/` и написаны с использованием фреймворка `pytest`.

-   **Асинхронный код:** Весь код базы является асинхронным, используя возможности библиотеки `asyncio`.

-   **Настройки конфигурации:** Вся конфигурация управляется через переменные окружения, как определено в файле `src/mqtt_kafka_connector/conf.py`. Предоставлен файл шаблона `.env.example`.

-   **Контекстные переменные:** Приложение использует контекстные переменные (`src/mqtt_kafka_connector/context_vars.py`), чтобы управлять специфичными для запросов данными, такими как `device_id` и `message_uuid`, среди асинхронных задач.
